# Shenanigans — Claude context

## Bazel setup

This repo is being incrementally migrated to Bazel, one directory at a time. The root `MODULE.bazel` is the single bzlmod workspace for all projects.

Key files:
- `MODULE.bazel` — bzlmod root; declares `rules_go`, `gazelle`, Go SDK version, and per-project go.mod deps
- `.bazelversion` — pins Bazel version for Bazelisk
- `BUILD.bazel` (root) — contains the `gazelle` runner target
- `.bazelrc` — workspace-level Bazel flags

### Dependency management

- Go deps are declared via `go_deps.from_file(go_mod = "//project:go.mod")` in `MODULE.bazel`, one entry per Go project
- Each project that uses external Go deps needs a corresponding `use_repo(go_deps, "...")` entry in `MODULE.bazel`
- `vendor/` directories are not used by Bazel — delete them once the Bazel build works
- The `bazel-*` symlinks at the repo root are Bazel output symlinks, not source files (in `.gitignore`)

### Gazelle

Gazelle auto-generates `BUILD.bazel` files from Go source. Run after adding/moving Go files:

```
bazel run //:gazelle
```

Each Go project directory needs a `# gazelle:prefix <module-path>` directive (matching the `module` line in its `go.mod`) so Gazelle generates correct `importpath` values. Without this it defaults to the root workspace module name + directory path, which is wrong.

Test deps generated by Gazelle may point at `//project/vendor/...` — replace those with `@repo_name//package` references to the external repos declared in `MODULE.bazel`.
